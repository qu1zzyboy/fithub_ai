# Agent 宏观架构

依据体育部门的业务流程图。这一份说明各段业务由谁完成、各自起什么作用，以及日后怎么判断改版是变好了还是变坏了。目录、表、技能文件、提示词和运行镜像留到某一段开工时再写。

教练面对的是同一个入口。业务上仍是流程图里的四段，从左到右各交一份产物，后一段只读前一段已经定下来的结果。

## 业务链

```mermaid
flowchart LR
  intake[需求归类]
  strategy[训练策略]
  framework[训练框架]
  session[这一次课]
  report[报告与调整]

  intake --> strategy --> framework --> session --> report
```

| 段 | 读什么 | 交出什么 |
| --- | --- | --- |
| 需求归类 | 教练说明的频率、周期、部位、动作模式、目标、项目、伤病、水平、器械；再对照训练类型与训练模块 | 训练策略 |
| 训练框架 | 已确认的策略；动作库、计划模板库、周期计划库 | Slot 编排和动作参数 |
| 任务分发 | 已落库的框架；这个人的评估、训练记录、动作能力、力量储备 | 这一次课：进退阶、强度、热身组、pre-set / after-set |
| 报告 | 当次课和一段时间的训练记录、评估、动作能力、疼痛、力量储备 | 给教练看的报告，以及下一阶段计划和参数的改法 |

队伍计划按人各走一遍任务分发，每人只看到自己的档案。负荷、容量、完成情况、进退阶、力量储备、可做与禁忌都收在报告这一段，不另开几条线。

## 对话与框架

这一段对教练可见，覆盖需求归类和训练框架。

它的作用是把教练的话收成一份能往下用的策略，并在教练点头之后生成框架。策略还没确认时，框架不生成。教练退回，就停在需求归类继续谈。

课前发内容和课后复盘不在这里做。这里只决定要不要把活交出去，并接收交回来的结论。

## 子 agent 与沙盒是预留的扩展位

Agent 之后是项目的重点，业务会比眼下这张流程图长。子 agent 和沙盒按这个来留：第一期用不满，但新场景加进来时，教练面对的入口不用拆开。

子 agent 承接一种会反复发生、又有自己的输入和结论的业务。沙盒承接一次要算的数。一种新业务如果主要是「读已有产物，交回一份结论」，就加一个子 agent；如果主要是「这个数还没有固定算法」，就放进沙盒，不为此再开一个 agent。两者都只有一层，做完把结论交回对话与框架，不再往下派。

第一期实际拉起的子 agent 是下面两个。它们看不到教练的原话，只拿到完成上一段所需的产物和这个人的档案摘要，也互不读取对方的内容。

| 子 agent | 完成流程图的哪段 | 起到的作用 |
| --- | --- | --- |
| 练前分发 | 任务分发 | 框架已经落库、课前要发内容时拉起。按这个人的档案把框架补成这一次课：热身组、pre-set / after-set、进退阶和强度。不改框架里的 Slot。队伍里每人单独发一次 |
| 练后 | 报告，以及计划和参数的微调 | 一堂课结束，或教练要复盘时拉起。交回给教练看的报告，以及下一阶段计划和参数的改法。改法回到对话之后停住，教练确认之后才写入 |

### 练后训练微调

这是练后子 agent 要完成的业务，也是后面最可能单独变厚的一块。

一堂课结束之后，它读当次课和一段时间的记录，看负荷、容量、完成情况、进退阶和力量储备，提出下一阶段怎么改：组数、强度、进退阶、下一次的动作参数。报告说明为什么改。改法本身不直接落库，回到对话里等教练确认。可做与禁忌仍由固定规则判定，微调不能把被拒绝的动作写回去。

第一期它和报告放在同一个练后子 agent 里，因为两份结论来自同一堂课。以后微调要按周期、项目或人群分成更细的规则时，可以把它拆成独立的子 agent，仍然只把改法交回对话。教练入口和确认点保持不变。

### 实时计算

教练在对话中途要一个仓库里还没有固定算法的数，例如这次课的某个强度储备，或一组临时对比。这次计算由练后放进沙盒当场完成，把数交回对话。没有当次课可复盘时，只交回这个数，不改计划，也不写报告。

沙盒的作用是这次数可以算，但算的过程碰不到档案库、碰不到别人的任务，也不能自己宣布某个动作可以做。算完的数回到练后，仍要过固定的分区和禁忌判断，通过之后才能进报告或调整方案。

以后课中对比、队伍汇总、临时指标变多，仍然走沙盒。每来一种数，不新开一个子 agent。

## 记忆

记忆解决的是下一轮还认不认识这位教练、这个学员。一次任务里的策略、框架、单次课和报告写在业务数据里，任务结束就以那份为准。记忆比任务活得更长：同一个教练下次再来，已经确认过的写法和近况还在，不用从头讲。

档案表里已有的伤病、重量、训练记录、评估、已落库的策略和课程不进记忆。那些以业务数据为准。记忆只记表里没有、但下一轮对话用得上的话。

### 三层，各管各的寿命

| 层 | 留下什么 | 保留多久 | 对谁生效 |
| --- | --- | --- | --- |
| 教练层 | 这位教练确认过的写法、偏好，以及对 agent 的纠正 | 随教练账号保留。账号删除时一起删 | 只影响这位教练之后的对话 |
| 学员层 | 表里没有的近况：这周膝不适、出差、口头定的这一周期侧重 | 随该学员保留，但有时效。过一段时间且教练没有再提起，就不再带入下一轮 | 只有对话绑了这个学员才读 |
| 系统层 | 不依赖某一个学员、又反复出现的通用说法 | 候选一直留着，但标成未生效或已拒绝。被接受的说法长期保留，不随某一个教练的账号删除 | 接受之后才对所有人生效。候选不影响任何一次生成 |

三层分开记，避免一位教练的习惯写进所有人，也避免某个学员的伤病写进教练画像。

### 怎么留下，怎么更新

只在对教练可见的一轮结束、并且这一轮已经有结论之后，才从教练的原话里抽取，写入上面三层。练前、练后的中间过程不写记忆。这一轮已经记过，就不重复记。

偏好和纠正必须能对应到教练说过的话。说不清是哪个学员的近况，不写入学员层。从 agent 自己的回复里反推出来的偏好不记。

教练可以手改自己的画像，以及自己名下学员的近期。手改的条目标成人工写入，之后的自动抽取不能盖掉。教练也可以关掉自己的自动记忆：不再抽取，也不再带入下一轮，已经留下的内容还在。

一条纠正先记在提出它的教练名下。同时满足三条，才另写一份系统层候选：不依赖某一个学员；同一教练反复说过，或至少两个教练说过；已接受的通用说法里还没有同等内容。接受或拒绝由运动科学或管理员做。拒绝的候选留在系统层里并标上拒绝，不删除，避免同一种说法被反复提上来。

### 下一轮怎么用

对话与框架每次先带上这位教练那一层里有哪些习惯。对话绑了学员，再带上该学员近期里还没过期的条目。系统层里已经被接受的说法，作为所有对话共同遵守的说明。具体一条要展开时再读那一条，不把三层全文塞进每一轮。

子 agent 不读记忆原文，只在这次任务说明里拿到有界摘要。这样以后子 agent 变多，也不会各自改同一份长期记忆。记忆不能把一个被拒绝的动作说成可以做。已接受的通用说法和某一段业务规则冲突时，以那段业务规则为准。

## 必须守住的

- 策略确认之前，不生成训练框架。
- 计划和参数的改法，教练确认之前不写入。
- 报告给教练看，不写进对话记录。
- 后一段只接收上一份已经落库的产物，不接收前面的整段对话。
- 一个动作能不能做，由固定规则判定。模型、沙盒和记忆都不能自行宣布。
- 沙盒只能读这次放进去的数据。实时计算只交回数，不改计划和报告。

## 评测

评测用来回答两件事：这一版做得好不好，以及不好具体出在需求归类、框架、练前、练后、沙盒还是记忆。模型、说明、知识库或技能有改动时，先用同一批样本回看，确认已经做对的场景没有退步，再让教练用。做法参照美团技术团队的 [《Agent 评测白皮书》系列 01：Agent 评测全览](https://tech.meituan.com/2026/09/10/Agent-Evaluation-White-Paper-01.html)。那篇文章把终局收成四个模块、两条循环和一套评测资产；冷启动不照着终局建全套，先让「改完能回看、坏了能复盘」转起来。

训练计划是长流程：有中间产物，没有唯一标准答案。评测看的是走过的路径和最终交出去的产物是否达标，而不是回复是否逐字相同。

**端到端看事有没有办成。** 按流程图的产物各留一批样本：

- 策略落在已定义的训练类型和模块里，并经过教练确认
- 框架先有 Slot，再有库内的动作参数
- 这一次课按该学员的档案补全，且没有改动框架里的 Slot
- 报告覆盖负荷、完成情况和禁忌；练后微调提出的计划和参数改法在确认之后才写入
- 实时计算交回的是这次要的数，没有改动计划和报告

**过程看坏在哪一段。** 端到端只说明这份计划不能用。过程样本用来区分是归类偏了、Slot 选错、练前用了别人的档案、练后的调整越界，还是沙盒的数进了报告但禁忌没拦住。项目刚开始只覆盖这几段，等真实问题反复出现在某一段里，再把那一段拆细。

**有些项一票否决。** 禁忌动作被写成可以做、未确认就写入计划、沙盒或记忆自行放行动作、练前改了 Slot、把别的学员的档案用到这个人身上。这些不过，这一版不能发布。写法、详略、报告好不好读，可以设成达到一定比例即可。

**改版之前先回看。** 同一批样本、同一套判断标准，只让待发布的版本变化。每个样本多跑几次，看通过率，不拿单次结果下结论。这道回看接进发布流程之后才有约束力。

**坏例要能复盘。** 至少留得下教练说了什么、走到了哪一段、交回了什么产物、教练有没有确认。凭这些能重现一个做错的案例，再决定是改 agent，还是改判断标准。判断标准本身判错时，去改标准，避免把 agent 调成只会迎合评测。

教练是否采纳、是否退回、报告是否被使用，是上线之后的业务效果。离线回看守住已经知道的问题；这些真实使用里的退回和投诉，用来发现评测样本里还没有的情况，并补进下一次的必过样本。
